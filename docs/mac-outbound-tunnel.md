# 国内出站隧道接入 Mac 网关

记录日期：2026-10-25（Asia/Shanghai）。目标是让中国大陆客户端只填写 HTTPS URL 和独立 API key，不需要代理、组网客户端或光猫管理权限。网关和 Claude 继续运行在 Mac 与隔离 VM；转发节点只承担入口流量。

## 当前状态

SakuraFrp 的官方 macOS ARM64 客户端已下载、按发布方校验值验证，并安装在宿主私有目录。已从用户授权的官方登录页面保存访问密钥，凭据文件权限为 0600、父目录为 0700；密钥未写入仓库、命令参数或聊天。

账户实名认证已由本人完成，已创建使用东莞双线 PLUS2 的免费 TCP 隧道，绑定免费域名和可信 HTTPS 证书，并完成公网模拟流式、上传、鉴权及后台恢复验收。Mac 通过普通用户 LaunchAgent 在登录后启动客户端，异常退出自动恢复；原 Funnel 作为另一个入口继续运行。实际 URL、节点端口、密钥及配置只保存在本机私有目录。

首次使用需要由本人在[官方页面](https://www.natfrp.com/user/realname)完成实名认证；[服务商说明](https://doc.natfrp.com/faq/realname.html)要求购买一次 1 元的认证资格并用支付宝完成本人验证。购买资格后还需提交认证并扫码，不能把支付成功当作实名完成。当前没有购买付费隧道套餐。

## 路径与边界

```text
大陆客户端
  → HTTPS / 国内 TCP 转发节点
  → Mac 普通用户 frpc（TLS 终止、严格选择预载证书）
  → 127.0.0.1:43158（既有客户端鉴权、会话隔离与限流）
  → 原内部网关 → host-only VM → 固定 VPS 出口 → Claude
```

1. 只创建一条普通 TCP 隧道，使用自动 HTTPS。上游固定为 `127.0.0.1:43158`，保留原始 HTTP Host，由网关的 `additionalPublicAuthorities` 显式列出实际域名及 `域名:分配端口`。不接受通配符、URL、凭据或请求头注入；未知 Host 或未列出的端口被拒绝。Origin 检查继续启用，不转发到 43157、VM relay、SSH、管理页或任意客户端指定地址。
2. 免费 `nyat.app` 子域名绑定到该隧道，并启用对应证书。客户端使用 `https://<分配的域名>:<分配的端口>/v1`；端口必须以实际分配为准。`auto_https_policy = strict` 拒绝没有匹配预载证书的 SNI，正常客户端继续验证系统信任链与实际域名。
3. 取得配置后，在本机保存经过检查的静态配置，只含这一条隧道。启动不使用 `--fetch_config` 或 `NATFRP_TARGET`，避免账户远程配置变化自动改变宿主上游。
4. 使用普通用户运行，关闭额外的内网监听、P2P/端口导出和管理服务；运行于[回环网络沙箱](../examples/mac-claude-vm/funnel-loopback.sb)下。该沙箱允许连接公开转发节点，同时拒绝除 43158 外的回环目标；它不是覆盖全部 LAN 地址或宿主文件的沙箱。
5. VM 的网卡、DNS、IPv6、UDP、宿主转发和专用 VPS 出口保持独立。新的入口不需要把 VM 改为 NAT 或桥接模式。

[隧道段配置示例](../examples/mac-claude-vm/sakura-api-tunnel.extra.example.ini)列出固定上游与 HTTPS 选项。它是需要合并到私有静态配置的片段，不包含可运行的账户或节点配置，不能直接启动。

在本机测试的 `0.51.0-sakura-15.1` 中，启用 `auto_https_verify_client = true` 后，正确的 Host 请求也返回 421；去掉 Host 改写后仍然如此。当前明确关闭该开关，并保留原 Host，由网关按上述显式白名单验证。未知 SNI 的服务端握手拒绝、错误 Host 的 403 和正常客户端的证书校验均已通过；这不等于完成了 HTTP Host 与 TLS SNI 的等值检查。不要重新开启该开关或恢复 Host 改写而跳过公网验证。

自动 HTTPS 在 Mac 上终止 TLS；免费域名的证书由服务商分发到客户端，信任范围包含域名与证书提供方，不能声称私钥只存在于 Mac。Claude OAuth、VM relay 密钥和内部网关密钥不提供给隧道服务商。

## 已完成的验收

以下为一条大陆电信线路绑定物理 `en0`、不使用代理的网络模拟测试，不包含 Claude 生成时间：

| 检查 | 结果 |
| --- | --- |
| 16 MiB 级 SSE 正文 | 16,856,079 字节，12.1974 秒，约 1.32 MiB/s；短流有突发带宽，不能把其峰值当作持续速度 |
| 模拟流式首帧 | 约 0.10 秒，在后端放行剩余正文之前到达 |
| 512 KiB 上传 | 524,335 字节，HTTP 往返约 0.368 秒，正文哈希一致；单独建立 TCP/TLS 约 0.031 秒 |
| 复用连接的模型目录请求 | 4 次请求中位数约 0.017 秒 |
| 模拟上游取消 | 公网客户端断开后约 0.10 秒传回上游 |
| 鉴权与路径 | 无/错误密钥 401，有效密钥模型目录 200，Origin 与未知 Host 403，管理路径和 health 404，并发超限 429 |
| 异常恢复 | 强制结束 frpc 后由 LaunchAgent 自动恢复；重新通过公网严格 TLS 约 0.58 秒，有效密钥模型目录再次返回 200 |
| 监听与文件权限 | frpc 无本机 TCP 监听；配置、密钥 0600，私有目录 0700 |

上海电信、深圳联通、广州移动、北京联通的四个外部 Globalping 节点均完成 DNS、可信 TLS 和无密钥 401 响应，总耗时分别约 120、59、48、155 毫秒。该测量没有把生产密钥交给第三方探针，只证明这些线路的 HTTPS 可达与拒绝鉴权行为，不代表这些线路的已认证调用或持续吞吐都已验收。

宿主运行中的 Mihomo 控制接口显示 frpc 的节点连接选择 `DIRECT`；本机测试客户端的 DNS 查询和 HTTPS socket 另行绑定物理网卡，因此没有把经 VPS 的测试结果当成大陆直连。Mac 的日常 TUN 仍存在；改变宿主代理模式或规则后应重新检查连接路径。

网络模拟使用一次性测试身份和隔离后端，结束后恢复原外部入口。共享网关的 13 项相关测试通过，其中新增的检查覆盖显式 Host/端口、非法配置和跨入口共用配额。Claude 尚未登录，真实模型调用、速度和账号权限仍待后续验收。VM 网络策略未改。

## 后台服务与后续验证

使用 [LaunchAgent 模板](../examples/mac-claude-vm/local.claude-vps.bifrost-sakura.example.plist)，将 `ACCOUNT` 和路径替换为当前账号，再将回环沙箱模板复制到私有目录中的 `sakura-loopback.sb`。设置工作目录和 `Umask = 077`，并预先创建权限为 0600 的日志文件。启动前核对官方二进制校验值、私有静态配置，以及网关中明确列出的公开 Host。

服务通过 `env -u` 清除 `NATFRP_TOKEN`、`NATFRP_TARGET` 与代理环境变量，使用 `-c` 加载本机静态配置，`-n` 关闭更新检查，`--proxy none` 关闭显式代理。这个选项本身不能绕过 TUN，实际节点连接仍需检查。模板不包含账户密钥，也不注册启动器的远程管理功能。当前自动加载证书和重启后的证书恢复已验收，跨到期续期仍依赖服务商。

免费账户的用户组标称限速为 10 Mibps，月基础流量为 5 GiB，不能据此推断实际吞吐或跨运营商速度。测试前不购买升级套餐。

- 更换节点、证书或客户端版本后，重验域名解析、严格 TLS、无/错误 API key 拒绝、有效 key 的模型目录、Origin、管理路径和未知 Host 拒绝。所有入口共用原 43158 进程的会话与限流状态。
- 绑定物理网卡验证公网访问，不仅关闭 HTTP 代理；检查宿主 frpc 到国内节点的实际连接也没有走 VPS。否则不能称为客户端无需 VPS 的实测。
- 使用隔离模拟后端和一次性测试身份，比较小请求延迟、至少 512 KiB 双向传输，以及 SSE 首帧是否在后端放行剩余正文之前到达；确认客户端断开会取消上游。网络验收不需要 Claude 登录，也不代表真实模型速度。
- 覆盖实际使用的电信、联通、移动或工作网络，记录线路、时间与样本范围。节点地名、带宽宣传和本机回环结果均不能代替这些测试。
- 重新部署时，先通过公网测试，再注册专用 LaunchAgent，验收异常退出恢复、隧道重连及证书重新加载。Mac 需要保持开机、用户登录及联网。
