# 用户账号与 API Key 接入

Bifröst 将上游渠道账号与下游接入用户分开管理。管理员维护 B、CodeBuddy、Cursor 等渠道；用户注册自己的 Bifröst 账号，取得独立 API Key，在 CodeBuddy、WorkBuddy 等客户端中使用管理员分配的模型。

## 入口与首次启用

- 本机管理页：`http://127.0.0.1:43155/`。第三个页签 **接入用户** 用于创建用户、分配模型、设置 Key 授权截止、停用账号、管理 Key 和邀请码。上游渠道登录仍在 **账号管理** 中维护。
- 用户门户：`http://127.0.0.1:43159/portal`，也可通过 `/register` 或 `/login` 打开。用户可以注册、登录、查看获准模型、创建和撤销自己的 Key。
- 客户端 API 基础地址：`http://127.0.0.1:43159/v1`。

网页静态文件刷新后可更新。首次加载用户接入后端需要重启 Bifröst，**由用户自行选择时机重启**；现有模型请求会受重启影响。重启后在“接入用户”页签确认入口已就绪，再打开用户门户。

用户入口是独立 HTTP listener，默认仅监听本机 `127.0.0.1:43159`，避开旧 With MCP 的 43158 端口。它不挂载 `/api/*` 管理员接口；用户会话与本机管理员会话分开。入口配置错误或端口被占用时，会报告用户入口未启动，原有主网关仍可运行。

## 注册、授权与密钥期限

默认允许无邀请码注册。注册成功会创建账号及第一个 Key；支持凭据保护的统一用户页可在登录后再次主动查看或复制。无邀请码的账号默认没有模型权限，由管理员在“接入用户”中分配。使用有效邀请码注册时，仅继承该邀请明确指定的模型。管理员也可以将注册策略改为仅邀请或关闭注册。

账号启用状态与 Key 有效期是两件事：

- **停用账号**：所有 Key 立即无法调用，已有用户中心会话失效。重新启用后，未到期且未撤销的 Key 才可能恢复使用。
- **Key 到期或停用**：影响该 Key 的模型调用，不删除账号。用户仍可登录用户中心。
- **撤销 Key**：该 Key 永久失效；需要继续使用时创建新 Key。

默认账号的 Key 授权截止是注册后 **30 天**。自助创建 Key 时，实际到期时间取“申请的到期时间”和“账号授权截止”的较早者。因此，反复新建 Key 无法绕过一个月的授权期。授权期结束后，需管理员先延长账号的 Key 授权截止；账号本身不会因这一截止而被删除。延长截止不会自动延长旧 Key 自身的到期时间。

完整 Key 在注册、创建成功或本人登录后点击“查看／复制”时返回，默认页面和管理列表只提供末四位等安全信息。统一账号库保存校验摘要与绑定账号、Key 编号的 AES-GCM 密文；加密主密钥另由 macOS Keychain 或 Windows 当前用户 DPAPI 保护。旧版摘要记录在下次正常 API 认证时补存密文，不轮换 Key。未启用凭据保护的旧部署仍只能在生成时复制。网页切到后台、隐藏或退出后清除原文；重置、撤销或停用后的旧 Key 不能再查看。用户只能读取自己的当前有效 Key，不能读取其他账号。

备份需同时保留状态目录下的 `client-access.json` 和 `client-key-protection.json`，并确保原系统用户的 Keychain／DPAPI 仍可用。复制这两个文件到另一台机器不代表可以恢复 Key 原文；无法解密时保留原有校验与调用能力，网页明确报错，不自动轮换用户 Key。

## 余额、Token 配额与扣费账本

“接入用户”页签现在也管理每个用户的余额、Token 总配额和账单。管理员选择用户后读取该用户的账单与待核对请求，可点击“更多账单”“更多待核对”继续查询历史，不受全局最近流水条数影响。用户门户与微信小程序只读展示本人余额、预留、可用余额、本周期用量、剩余 Token 和最近 50 条账单。旧后端没有返回计费信息时，页面显示“待更新后台”，不会用零余额代替未知值。

余额以人民币记账，`1 元 = 1,000,000 微元`；输入金额与模型价格最多支持 6 位小数。后台仅提供**管理员记账**：输入正数充值，输入负数扣减，可附备注。没有接入微信支付、银行卡、自动充值或支付回调。管理员记账本身不会向上游购买额度，实际模型调用仍使用所绑定渠道账号的额度。

后续[自动充值需求与接入设计](automatic-topups.md)要求支付成功后自动入账，订单绑定网页账号并通过正式支付接口核验。当前尚未开通真实支付，商户主体及产品权限待准备。

首次配置可按以下顺序操作：

1. 在“模型计费价格”选择模型，填写未缓存输入、缓存输入、输出价格，单位均为 **元 / 百万 Token**。填写该模型的请求预留输入、输出 Token，启用并保存。费率不预置厂商价格，必须由管理员明确填写；没有有效价格与预留配置，不代表免费。
2. 选择用户，设置独立的 Token 总配额，留空表示不设上限。需要余额扣费时勾选“启用余额计费与余额检查”，并为用户充值。旧用户默认不启用余额计费。
3. 保存后使用该用户的 Key 调用。启用余额计费或 Token 配额时，获准模型还必须有有效、已启用的计费配置，否则请求会被拒绝。关闭余额计费时只计 Token，不扣余额；Token 配额仍可独立拦截请求。

请求开始前会按模型配置预留余额和 Token，用于并发请求的额度检查。余额计费开关与费率在接受请求时固定，后续修改只影响新请求。这里的预留是管理员设置的预算，**不是精确 Tokenizer 结果，也不是模型的硬输出限制**。正常结束且返回可核实用量后，按真实输入、缓存输入与输出结算，释放原预留。Token 总配额按输入与输出合计统计，缓存输入已包含在输入内，不能再次相加。金额合并计算后向上取整到 1 微元。实际用量可能超过预留并产生欠费，后续请求会依据新余额和用量重新检查。

失败或输出达到长度限制的响应，如果包含可信实际用量，也会按实际消耗结算；明确拒绝且没有用量的请求释放预留。断流、缺失完整用量或服务重启时，请求可能进入“待核对”并继续占用预留。管理员需要核实上游实际用量，在账单中选择按真实用量结算；只有确认未产生用量时才释放预留。页面不会把未知用量自动记为免费成功。存在预留或待核对请求时，不能开始新的 Token 配额周期；没有挂单后，可以明确确认并重置本周期已用 Token，历史账单继续保留。

余额调整和人工核销使用独立操作 ID 防止重复入账。网络中断或响应不完整时，页面会保留原参数及操作 ID；点击重试继续同一笔操作。当前浏览器页签的刷新也会保留未决操作。完成确认前不能把同一笔调整改成另一金额。浏览器需允许会话存储；无法保存未决操作时，页面会在发送前拒绝新调整。未确认操作达到 100 笔时，先核对旧操作，再提交新调整，页面不会删除旧操作 ID 腾出位置。

计费账本只覆盖此用户入口接收的请求。其他电脑直接调用上游、或使用原有主网关的流量，不会被记作该下游用户的扣费账单。模型设置的本地销售价格也不代表厂商实际收取的金额。

账本保存在私有状态目录的 `client-billing.json`，目前按单进程、单实例写入。此版最多保存 2048 个计费用户、1024 条费率、10000 个请求和 50000 条历史记录，文件不超过 64 MiB。达到保存上限会明确拒绝新操作并保留原账目，不会静默删除历史；自动归档尚未实现。重复提交充值或核销会沿用同一操作编号；重新发起模型推理则属于新的调用，不按消息正文去重。

## 模型与协议

管理员逐个分配明确的 B、CodeBuddy、Cursor 模型 ID。公共入口不开放账号 A，也不会自动授予新增模型。模型还需在网关当前目录中可用并已启用，才能被用户调用。

| 接口 | 路径 | 可用渠道 |
| --- | --- | --- |
| OpenAI Responses | `/v1/responses` | B、CodeBuddy、Cursor |
| OpenAI Chat Completions | `/v1/chat/completions` | B、CodeBuddy、Cursor、已配置的隔离 Claude |
| Anthropic Messages | `/v1/messages` | CodeBuddy、已配置的隔离 Claude |
| 已授权模型目录 | `/v1/models` | 只返回此 Key 获准且当前可用的模型 |

Responses 与 Chat 通常使用 `Authorization: Bearer YOUR_BIFROST_API_KEY`；Messages 也支持 `x-api-key`。用户中心登录会话不能代替模型调用 Key。

Chat 入口负责将客户端格式转换为网关 Responses 格式，支持已适配的文本、图片、工具调用及 SSE。工具在客户端执行，网关负责返回调用及接续结果。附件、思考和其他能力仍取决于所选模型与渠道适配；未适配内容会返回明确错误。Cursor 的兼容提示方式也保留其原有边界。Messages 不会把 B 或 Cursor 请求自动切换到其他协议。

## CodeBuddy IDE

在用户级 `~/.codebuddy/models.json` 的 `models` 数组中添加模型，保留已有配置。`id` 使用用户门户显示的获准模型 ID，`url` 使用**完整 Chat 接口地址**，`apiKey` 填本次创建的 Bifröst Key。例如：

```json
{
  "models": [
    {
      "id": "claude-codebuddy-opus-5-5",
      "name": "Bifröst · CodeBuddy Opus 5.5",
      "vendor": "Bifröst",
      "url": "http://127.0.0.1:43159/v1/chat/completions",
      "apiKey": "YOUR_BIFROST_API_KEY",
      "supportsToolCall": true
    }
  ]
}
```

示例中的 Key 是占位文字，需替换为自己创建的 Key。模型必须已分配给该账号。其他电脑不能使用指向宿主机的 `127.0.0.1` 地址，需要先配置可达的 HTTPS 入口。

CodeBuddy 官方说明 `url` 必须是完整 API 路径，且 IDE 自定义模型使用 OpenAI 接口格式；参见 [models.json 配置指南](https://www.codebuddy.cn/docs/ide/Features/models)。

## WorkBuddy

打开 **设置 → 模型 → 自定义 / Custom**，填写：

1. URL：用户门户显示的完整 Chat 接口地址。
2. API Key：自己创建的 Bifröst Key。
3. 模型名：门户显示的获准模型 ID。

WorkBuddy 默认校验并补全 `/chat/completions`；标准完整 Chat 地址保持默认即可。**自定义协议**用于确有非标准路径的接口。保存后，在自定义模型分组选择该模型。参见 [WorkBuddy 官方模型配置说明](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)。

macOS 5.9.3 的公网用户 Key、Sonnet 聊天与 Opus 客户端文件工具验收见 [WorkBuddy 客户端](workbuddy-client.md)。这里验证调用兼容性；原生自定义入口仍需逐个配置模型，不会仅凭 URL 与 Key 自动订阅整个模型目录。

## 入口配置与外网部署

配置示例位于 [client-gateway.example.json](../config/client-gateway.example.json)。将其复制为 Bifröst 状态目录中的 `client-gateway.json` 后修改。该文件只描述入口，不填写模型 Key 或用户密码。

- `enabled`：是否启动用户入口。
- `listener`：独立本机监听地址、端口和允许的 Host。当前仅接受回环地址，不能直接改成 `0.0.0.0`。
- `publicBaseUrl`：门户及 API 对外使用的 origin，只包含协议、主机及可选端口，不附加 `/portal` 或 `/v1`。本机 HTTP 可用；外部域名必须使用 HTTPS。

外网部署时，将自有 HTTPS 域名反向代理到本机用户入口 `127.0.0.1:43159`，并将 `publicBaseUrl` 改为该 HTTPS origin。代理传入的 Host 应匹配该 origin 或 `listener.allowedHosts`。**不要把管理端口 43155 作为公开代理目标。** 新配置在下次重启后生效。

上面的回环地址是通用部署示例；现有 Mac 公网入口与隔离 Claude 的部署边界另见 [Mac Claude VM](mac-claude-vm.md)。

## 微信小程序

源码在 [wechat-miniprogram](../wechat-miniprogram/README.md)，复用用户注册、登录、模型、Key 与个人账单接口，展示余额和 Token 配额。当前采用用户名密码登录，不包含微信一键登录或微信支付；密码与 API Key 不写入小程序本地存储，用户中心会话仅保存在内存。

正式使用还需运营方提供小程序 AppID，在 `config.js` 填写已部署的 HTTPS 服务 origin，并在微信后台配置 **request 合法域名**。域名及证书须满足微信要求，包括有效完整证书链和 TLS 1.2。`touristappid` 与 `.example` 地址仅为开发占位。

微信开发者工具编译、设备预览、域名配置、审核和发布尚未完成。后续若接微信身份登录，需要服务端完成 `wx.login` 临时 code 的兑换与账号绑定，不能在小程序中放置 AppSecret 或下发 `session_key`。

微信官方依据：[网络要求](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)、[wx.request](https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html)、[小程序登录流程](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)。文档核实日期：2026-10-23。
