# 本机客户端管理

管理页的 **客户端接入** 集中提供客户端启动、网关接入、恢复原生、目录同步及调用路径预览。这里只管理运行 Bifröst 的这台电脑；虚拟机或其他电脑上的客户端仍需在所在环境管理。

## 启动和模式

| 客户端 | 网关接入与恢复 | 目录更新 |
| --- | --- | --- |
| Codex | 通过官方配置接口同时切换内置 OpenAI 与已接入网关提供方的路由，覆盖已有会话 | 模式切换须完全退出并重开；模型目录由网关实时维护 |
| CodeBuddy | 向用户级 `models.json` 加入本网关模型；恢复原生时撤销本桥写入的模型 | 自动或手动同步已开放模型，保留其他自定义模型和原模型 |
| WorkBuddy | 向独立用户目录的 `models.json` 加入本网关模型；恢复时撤销本桥模型 | 同 CodeBuddy；客户端实际重载状态需以界面为准 |
| Cursor | 可启动本机已安装应用；本地网关接入尚未适配 | Cursor 目前作为上游额度来源，不因此视为已适配的调用客户端 |
| Claude | 当前虚拟机部署不由宿主机启动按钮控制 | 原有虚拟机配置和出口继续由所属环境管理 |

启动按钮只打开受控识别到的本机应用，不自动结束正在运行的应用。Codex 的提供方切换需重新加载；CodeBuddy 与 WorkBuddy 的网关模型和内置模型共存，加入模型不代表当前聊天已经选用它。

## Codex 已有会话与连接切换

Codex 会保留每条会话创建时的提供方。仅修改全局 `model_provider` 不会改变原来绑定 `openai` 的会话；即使菜单显示网关模型，请求仍可能直接到官方并被拒绝。

网关模式现在同时维护内置提供方的 `openai_base_url` 和已有网关提供方的连接字段。内置提供方使用只限本机的独立授权入口，保留当前客户端的 OpenAI 认证，沿用同一套 A/B 分流；普通模型保持 A 的请求与认证，B 别名使用独立 B 授权。该入口的地址包含私有凭证，不应复制到日志、截图或共享配置。浏览器和远端连接均不能使用它调用模型或管理接口。

原生模式恢复两处路由的原始值。配置修改通过官方编辑器一次提交，并保存原值用于恢复；用户后来修改受管字段或存在更高优先级覆盖时，操作会报冲突。会话 ID、消息、工具历史和模型偏好不被迁移。原生模式下仍选着网关模型的会话需手动选择普通 GPT 模型。

网页显示的是已保存配置。**完全退出并重开 Codex 后**，已有窗口才会加载新连接。旧版本用户可在当前模式下点击“更新网关连接”或“更新原生连接”，补齐路由后再重开，无需逐条修复会话。

离线验证可运行 `node scripts/verify-codex-native-routing-offline.mjs --binary <Codex-CLI-绝对路径>`。它创建独立配置和假凭证，使用本地模拟上游，验证同一旧 `openai` 会话的目录、WebSocket 回退、A/B 切换和凭证隔离；不会调用真实模型或修改用户配置。官方配置依据：[Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced)、[模型目录](https://learn.chatgpt.com/docs/model-catalogs)。

## 普通模式提问

Codex 的提问、文件操作、终端命令和权限确认由当前客户端执行。模型经网关返回工具调用后，客户端决定是否执行并回传结果；不因模型来源不同而在网关另建问答界面。

CodeBuddy、Cursor 和通用远端模型目录启用 `apply_patch_tool_type = "freeform"` 与 `multi_agent_version = "v2"`，避免因缺少声明而隐藏 Codex 的本地补丁和子代理工具。仍使用直接工具调用，工具执行服从当前客户端的沙箱与审批；源端模型的思考、图片、并行工具和上下文能力继续按实际目录发布。目录更新首次加载需要重启网关，并让 Codex 重新读取模型目录。

本机官方 CLI `0.166.0-alpha.6` 的 `request_user_input` 默认只能在 Plan 模式执行。若普通模式返回 `request_user_input is unavailable in Default mode`，在当前用户 `config.toml` 已有的 `[features]` 表中加入或更新：

```toml
[features]
default_mode_request_user_input = true
```

已有 `[features]` 时只添加这一项，不重复创建表。完全退出并重开 Codex 后加载；网关无需因此重启，原生／网关路由切换也不删除此用户偏好。这是本机官方二进制已注册、标为 `under development` 的实验开关；其他版本应先用 `codex features list` 核对是否支持。

`npm run verify:codex-questions` 在隔离配置下验证三种情况：普通模式默认拒绝、Plan 模式提问成功、普通模式启用后提问成功。成功场景必须收到官方 `item/tool/requestUserInput` 请求，并将选项答案完整送回下一次模型请求。测试使用假上游和自动回答，不消耗真实模型额度；不把协议验证当作实际桌面点击验收。

客户端工具的兼容不代表不同模型具有相同的推理质量或上游服务。OpenAI 托管搜索、结构化输出保证和其他来源无法解密的原生压缩密文仍有独立边界；可用的客户端联网、MCP 和插件工具沿用客户端提供的工具声明。

## 侧边聊天与切换模型

Codex 的侧边聊天会复制父聊天历史并创建新的 thread。远端 Bifröst 通过本地 Messages 转换层生成的思考与压缩状态属于可复制的历史快照：绑定当前接入用户、来源、模型、协议和授权，允许同一用户的分叉继承。CLI 执行会话仍按每条 thread 独立绑定，父子可以分别续聊，子聊天不会消费父聊天等待中的工具回调。未知远端原生 Responses 句柄不据此视作可复制快照。

旧版按 thread 绑定的历史会先经过外层和内层验证，再迁移为快照。Codex 的父聊天提示只提供本地解密候选，不能替代用户或来源授权；已验证分叉关系保存在私有数据目录的 `remote-fork-lineage.json`，只记录用户范围的哈希与父子标识，不记录聊天正文或模型密文。该索引最多保存 8192 条关系、单次最多检查 64 个祖先候选；无法验证的旧历史会明确报错，不删除压缩摘要。

更早的 v1 封装没有来源模型提示。网关会在当前已登记的模型中进行本地认证，成功解封后才确定来源；512 项缓存只记录已认证的模型 ID，命中后仍重验授权与密文。单个旧状态上限 8 MiB，同一请求的验证累计上限为 128 MiB、4096 次尝试和 1 秒；超限明确报错。这一步不发送候选模型推理请求。

远端 Claude 的额度耗尽后，仍可在原聊天选择原生 GPT。已保存思考或压缩摘要在本地认证和交接，不为识别旧历史而调用旧模型。需要新压缩时，由 Codex 使用新选定的模型发起；不会为成功切换而要求旧 Claude 再生成一轮回复。缓存是否命中仍按所选模型自己的前缀和有效期决定。

这些后台修复首次加载需要在网页重启 Bifröst，之后可以回到原侧聊或原聊天重试。既有聊天 ID 和持久历史保持不变。

## 自动与手动同步

自动同步默认开启，但只有客户端已经处于网关模式时才写入目录。原生模式不自动改变客户端配置，也不会因为远端目录变化而切换模式。

网关约每 30 秒检查来源目录并同步变化。**立即同步**会主动刷新来源目录后同步；关闭自动同步仍可使用这个按钮。只有在网页已勾选开放且来源当前可用的模型才会同步，新发现但尚未开放的模型不会自动启用。

Codex 账号 B 在模型管理中显示该账号官方目录的完整列表，保留已有选择，新发现的模型默认关闭。目录缓存按账号、用户、授权代次和客户端版本隔离；“刷新账号目录”和“立即同步”会强制更新 B 目录。客户端只收到已开放且当前可用的条目，模型 ID 使用 `B-<上游 ID>`，显示前缀仍由账号池设置。

页面区分网关最新目录、已同步配置和客户端重载提示。“目录已同步”表示本桥完成目录或配置维护，不证明客户端当前模型菜单已即时更新，也不代表每种工具、附件和思考能力均已验收。

## 模型名称与顺序

在 **账号池 → 选择账号 → 模型名称与排序** 中设置该来源的模型前缀和排列顺序。显示名统一使用“前缀 · 原始模型名”；前缀可为空。例如 `Codex B · GPT-6.1 Sol`、`CodeBuddy · Opus 5.5`、`Bifröst · Claude Opus`。模型 ID、来源绑定、授权和既有会话保持不变；前缀不是 API 请求中的模型 ID。

展示名超过客户端的 256 字符长度限制时，目录和预览会用省略号缩短；完整原名与模型 ID 仍保留，不影响请求路由。

原生 A 模型固定在第一组；其他账号按排列顺序从小到大显示，同一账号的模型连续排列。相同顺序按账号原先的登记顺序稳定排列，各组内沿用上游模型顺序。每个远端 Bifröst 账号可分别设置前缀和顺序。默认顺序为 A、Codex B、CodeBuddy、Cursor、Claude、With、远端 Bifröst，未配置的来源不发布模型。

保存后新读取的管理目录与 Codex 目录立即采用展示设置；CodeBuddy、WorkBuddy 在网关模式按原来的自动／手动同步设置更新。已打开客户端可能需要重新读取目录或重开才能显示新名字。首次加载此功能需空闲重启网关，此后修改展示设置无需重启服务。

Codex 保留现有 `model_catalog_url`，同步不替换提示模板、账号认证或模型偏好。CodeBuddy 默认使用 `~/.codebuddy/models.json`；WorkBuddy 使用 `WORKBUDDY_CONFIG_DIR`、兼容的 `CODEBUDDY_CONFIG_DIR` 或 `~/.workbuddy/models.json`。配置由客户端工作区覆盖时，仍需在客户端检查实际生效的模型目录。

文件型适配器记录自己插入的条目并维护写前恢复记录；恢复原生仅撤销本桥拥有的模型和相关筛选项。名称冲突、外部修改、损坏文件或写入竞态会明确报错，保留其他配置。客户端管理状态保存在私有数据目录中，不进入项目仓库。

## 每个模型的上下文预算

在 **控制台 → 模型选择 → 展开账号** 中，为各模型选择“跟随模型默认”、目录提供的上下文档位，或输入自定义 Token 数。与模型开关一起点击“保存模型设置”；选择“跟随模型默认”会清除该模型的覆盖值。页面分别显示当前客户端预算和源端默认值，例如“目录默认 300K · 已保存预算 600K”。

目录在保存期间更新时，页面只合并你实际修改的字段，并最多重试一次；其他页面保存的无关模型设置会保留。若同一字段被别人修改、保存失败或无法确认保存结果，页面保留你的草稿并显示原因，不会静默恢复默认值或把未确认的结果显示为已保存。

CodeBuddy 的模型目录会保留默认长度和可选档位。例如，当前 Opus 5.5 与 Kimi 3.1 Pro 声明默认 300K，可选 300K、600K、1M。网关不再将这些声明统一截成 200K；Cursor 和远端来源也优先使用它们实际声明的窗口。没有窗口声明的来源仍保留适配器默认预算，并在管理页说明上限未知。

自定义值可以低于声明的最大值，不必恰好等于一个档位，例如在 1M 上限内设置 450000。输入必须是 1000 到 10000000 之间的整数 Token 数，已知上游上限时不能超过该上限；上限未知时，自定义只代表管理员设置的客户端预算。设置不会扩大模型实际能力，也不等于已完成满窗口测试。

这项设置控制 Codex 模型目录中的上下文预算；Codex 仍会预留安全余量，并按自己的自动压缩策略触发压缩。直接配置的 `model_context_window`、`model_auto_compact_token_limit` 等 Codex 覆盖项仍可能改变客户端行为。保存后重新读取 Codex 模型目录，必要时完全退出并重开 Codex。网页不会自动关闭客户端；这项设置也不会修改其他客户端自己的压缩策略。

预算覆盖与模型开关一起保存在节点私有配置中。刷新目录、切换原生模式、重启节点不会清除覆盖。若新的来源目录声明了更低上限，管理页保留旧值并标出失效，发布目录会采用新的模型默认值；可重新设置或恢复默认。新版本第一次加载需要重启网关，后续保存预算无需再重启网关。

管理接口：`POST /api/model-settings` 使用原有 `revision`、`disabledModels`，可额外提交 `contextWindows: { "模型ID": 1000000 }`。该对象按模型打补丁；值为 `null` 时恢复默认，省略字段或未列出的模型保留原设置。保存仍使用版本核对与原子写入。窗口声明、预算覆盖和真实验证状态分别展示。

## 本机模型入口

本机 CodeBuddy／WorkBuddy 使用管理服务同一回环端口的 `/owner/v1/chat/completions`，模型目录为 `/owner/v1/models`。该入口复用现有 Chat／Responses 转换和本机网关模型凭证，只开放已启用且可通过 Responses 调用的独立来源，账号 A 不发布到这里。管理页直接写入受控客户端配置，不向网页返回模型调用 Key。

这个入口与注册用户的 `/v1` 入口分别鉴权，不创建下游用户、销售账单或新 Key，也不开放管理员接口。来源请求继续经过原有路由、Token 记录和诊断；其他电脑仍应使用各自的用户 Key 和已配置的用户入口。

## 来源与协议

账号池描述凭证归属、额度和模型；客户端接入描述本机配置；协议适配描述某次调用经过哪些转换。A 登记为 `codex-client` 来源，保留随请求使用调用者认证的方式；B 使用独立授权，两者不会合并凭证。

调用路径预览按入口协议与来源匹配。协议已实现、入口已启动、来源已就绪与客户端真实验收分别展示。Claude 的 CLI 适配和远端节点的内部链路不会被描述成无条件 HTTP 透传。

官方配置依据：[CodeBuddy 模型配置](https://www.codebuddy.cn/docs/ide/Features/models)、[WorkBuddy 模型配置](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)。客户端具体版本的热重载能力以其实际行为为准。
