# CodeBuddy 模型自动同步

Bifrost 的客户端适配层已提供 CodeBuddy 模型文件投影。新版网关运行期间，每 5 秒检查一次同步设置，启用的来源默认每 30 秒读取一次受认证保护的标准 `/v1/models` 目录。模型新增、名称或能力变化、撤回授权均通过当前目录同步，不需要重启网关或 CodeBuddy。它是客户端电脑上的功能，远端 Mac 不能替没有安装本地同步器的用户修改配置。

CodeBuddy 官方支持 [`models.json` 热重载](https://www.codebuddy.cn/docs/ide/Features/models)。本机 4.12.3 验收发现原子替换模型文件与其文件监听存在兼容问题；测试窗口重载一次建立监听后，使用保留文件标识的写入，菜单连续完成 A→B→移除，后续不需重载。若客户端此前已丢失监听，首次启用后可能需要重载一次窗口；日常模型更新不需要逐个添加或重新输入 Key。

## 启用

在运行本地 Bifrost 的同一系统用户下执行：

```text
node scripts/client-sync.mjs enable --url https://你的用户API地址/v1 --key-stdin
```

Key 由标准输入传入，不放入命令参数。可指定 `--state-dir`，默认沿用 `BRIDGE_STATE_DIR` 或原网关状态目录；`--target` 默认是当前用户的 `~/.codebuddy/models.json`。本机标准 API 可以使用 HTTP 回环地址，其余来源必须是 HTTPS。这里需要提供标准 `/v1/models` 目录，不能将 Codex 专用的 `models/slug` 目录当作标准目录。

Windows 原有 `Start-Bridge.ps1` 网关更新到包含此功能的版本后会装配同一个同步器；后续启用或变更同步设置无需重启服务。凭据由当前用户 DPAPI 保护；macOS 使用当前用户 Keychain 与 AES-GCM，凭据还绑定具体来源地址。CodeBuddy 自身需要在其模型配置中持有调用 Key，生成文件使用仅当前用户可读的权限；不要把该文件、状态目录或备份提交 Git。

```text
node scripts/client-sync.mjs status
node scripts/client-sync.mjs once
node scripts/client-sync.mjs disable
```

`once` 只拉取目录，不发起推理。`disable` 停止后续同步并保留当前配置。重新启用时仍保留原有受管项的归属记录和用户修改，不强行接管同名模型。

## 合并与故障边界

- 只管理该同步实例实际创建且内容未被手动修改的模型。其他自定义模型、根配置与原有可见性过滤保留；不会覆盖同名但不属于它的模型。
- 新目录移除模型时，只移除其未被修改的受管项。手动修改、删除受管项会保留用户意图并报告 `conflict`，不会每 30 秒强行改回。
- 目录内容没变时不重写配置，避免干扰正在使用的客户端。目录认证、网络、格式或写入失败时保留最后一次成功配置，状态显示 `unavailable`；不会切换来源、改用其他凭据或重试推理。
- 归属记录使用原子替换和持久的写入意图。CodeBuddy 4.12.3 的监听在原子替换模型文件后可能失效，因此目标文件保留原文件标识，以兼容其持续监听。写入前保存仅当前用户可读的恢复副本，成功提交后清除；该临时副本含客户端配置与 Key，不能提交 Git。写入中断后只恢复能匹配本次写入的部分内容，不覆盖无关的无效草稿。与其他编辑器同时写入时发现变化便停止本次写入，后续重读合并。
- 公网目录只返回该用户被允许使用且当前开放的模型。服务端启用、用户权限、费率和余额仍分别校验，不会因为客户端自动出现新模型而自动扩大权限或赠送额度。
- 通用目录公开安全的名称、协议及能力投影；具体客户端的字段命名保留在 `src/clients/codebuddy.mjs`。新增客户端不应修改供应方路由逻辑。

Mac 用户入口的 Chat 分流已补为：受管 Claude 直接使用其接口，其他模型使用自己的 Responses 来源再转换为 Chat，避免把新增 Cursor 等来源的 Chat 请求固定交给 Claude。该项由离线来源及计费测试覆盖，不代表已经完成真实 Cursor 登录和推理验收。Cursor 不支持的 Messages 接入继续明确拒绝。
